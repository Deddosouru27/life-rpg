# Life RPG — контекст проекта

## Что это
Личный мотивационный движок Артура. Медиевал-фэнтези RPG, где реальные
действия питают прогрессию. PWA, телефон, офлайн.

## КРИТИЧНО: почему предыдущая версия провалилась
Старый Life RPG был таблицей: квест → +XP → цифра. Петля обрывалась,
интерес умирал за неделю. Новая версия обязана давать компаунд-прогресс:
взаимосвязанные ветки, мир реагирует на действия, виден накопленный итог.
Если фича не усиливает петлю — её не делаем.

## Три священных правила
1. ЧЕСТНОСТЬ ДАННЫХ. Обманул систему = обманул себя, тогда это просто
   анимации. Любая механика, позволяющая накрутить прогресс, — критический
   баг, не UX-мелочь. XP, золото, уровень, HP, стрики обязаны быть ЧИСТОЙ
   ФУНКЦИЕЙ от записей о выполнении в БД. Никогда не инкрементировать
   состояние мутацией в обработчике клика.
2. ОДИН ТАП. Отметка действия — один тап. Никаких форм на 5 полей.
   Механика снижает трение реального действия, а не добавляет.
3. БЕЛАЯ ШЛЯПА ОКТАЛИЗА. Смысл, достижения, развитие — да. Дефицит,
   искусственная тревога, зависимость — нет. Мотивация должна быть
   устойчивой, а не аддиктивной.

## Определение готовности
Зелёный билд — НЕ готовность. Задача выполнена только после того, как ты
сам прошёл приложение руками в мобильном вьюпорте 390px и записал в отчёт,
что видел на экране:
1. Отметить привычку → откатить → отметить → откатить. XP, золото, уровень
   обязаны вернуться к исходным значениям.
2. Отметить все привычки дня. Проверить начисление и бонус.
3. Покупка при достаточном и недостаточном золоте.
4. Создать свою привычку → выполнить → удалить.
5. Создать квест → выполнить → откатить.
6. Перезагрузка страницы — состояние сохранилось.
7. Пройти все 5 экранов навигации и прочитать каждую надпись глазами.
   Непонятный элемент = баг.

Отчёт без пройденных сценариев не принимается.

## Правила интерфейса
- Любой элемент понятен человеку, открывшему приложение впервые.
  Требует пояснения — подпиши или убери.
- Эмодзи запрещены. Только SVG-иконки.
- Нижняя навигация — position: fixed + safe-area-inset-bottom.
- Акцентный цвет не более 10% площади экрана.
- Зоны нажатия не меньше 44px.
- Только токены дизайн-системы, произвольные значения запрещены.

## Технические правила
- React + Vite + TypeScript strict + Tailwind.
- IndexedDB (Dexie) — единственный источник правды. Работает офлайн.
- Игровая логика — чистые функции в src/game/, покрыты тестами.
  UI не содержит вычислений.
- Балансные константы — только в src/game/balance.ts.
- Никаких TODO и заглушек. Перед завершением: npm run build и
  tsc --noEmit проходят чисто.
- Vite: при проблемах с плагинами — npm i --legacy-peer-deps.
- .env редактируется руками в VS Code. Никогда echo, никогда в коммит.

## Fail-fast
Не прятать ошибки. Пустой catch запрещён — минимум console.error.
Если что-то не работает — падать громко, а не деградировать тихо.
